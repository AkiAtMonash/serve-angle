# 見返し画面の打点を1コマずつ直せるようにして、過去の動画で試す

## 目的

サーブの動画を見返すとき、自分の打点とプロのお手本の打点がずれて見えることがある。
自動で合わせたあと、ずれていたら「1コマ前」「1コマ後ろ」で直せるようにして、過去の動画で実際に試す。

## いまの状態（このブランチに入っている）

- 見返し画面の重ね合わせは、お手本の手で選んだ打点（`refs.json` の `impact`）に合わせる（`app.js` の `drawReview`）。
- 自分の打点は、検出したコマの0.033秒後（`CONTACT_LATE = 1/30`）。
- 見返し画面に「打点 ◀」「打点 ±0」「打点 ▶」を足した（`index.html`、`app.js` の `nudgeHit`）。
  - 押すと自分の打点が1コマずつ動き、お手本との重なりが変わる。
  - お手本の打点は動かない。
  - 見返しを開き直すと ±0 に戻る。
- `window.__rv` にレビューの状態を出してある（PCで試すとき用）。
- テストは61件通っている（`npm test`）。

## 決めたこと（Notion / DB_Skill_Grill-With-Docs）

- [0001 打点合わせは自動で行い、外れたときだけ1コマ直す](https://app.notion.com/p/4180bc4f733781959ab5fbcb4c5273e1)
- [0002 重ね合わせはトスから打点までの区間を伸縮する](https://app.notion.com/p/4180bc4f733781969aa9d459d5a711a9)
- 0003（5コマのボタン）は取り下げ。1コマを何回か押す。

守ること:

- スライダーは戻さない。5コマのボタンも足さない。
- お手本の `impact` の値は変えない（右54、右前30、右後ろ57、左後ろ58、左前54）。
- 打点の検出そのもの（`serve.js` の `findServes`）は、この作業では変えない。

## 試し方（PC）

1. リポジトリ直下で `python -m http.server 8899` を起動する。
2. `http://127.0.0.1:8899/?src=<動画>` を開く。`?src=` はカメラの代わりに動画を流す仕組み。
3. 撮る角度（右など）を選び、「この角度で撮る」を押す。
4. 録画して、見返し画面を開く。
5. 自動の打点が合っているか見る。ずれていたら「打点 ◀ / ▶」で直し、何コマで合ったかを記録する。

過去の動画は Google Drive の `PJ_TennisServe` にある。手元に持ってくるか、HTTPで読める場所に置く。

## 注意

- `?src=` の動画はループする。両手を上げる開始ジェスチャーで録画が始まるので、クリップの途中から録画されることがある。手動の録画ボタン（`#rec`）で最初から撮るほうがよい。
- MediaPipe のモデルは CDN から読むので、ネットが要る。初回は準備に数秒かかる。
- 見返しの動画は、録画したものをそのまま再生する。シークは重いので、コマ送りは録画中に貯めた静止画を使っている。
- 打点の1コマは、骨格のコマ（およそ1/15〜1/30秒）。動画のコマ（1/60秒）ではない。

## 受け入れ

- 見返し画面で、自動の打点が合っているかを目で分かる。
- 「打点 ▶」を押すと、お手本の骨格が1コマぶん動く。「◀」で戻る。
- ±0 に戻すと元に戻る。
- `npm test` が61件通る。
- 試した動画の名前、自動のずれ（何コマ）、直した後の値、スクリーンショットを残す。

## 止まる条件

- 見返し画面が開かない、または録画が始まらない（`?src=` の動画の長さ・形式による）。
- 1コマ動かしても見た目が変わらない（描画の更新が止まっている）。
- 直しても合わない動画が続く（検出そのものの問題なので、この作業の範囲外）。
